# Compliance OS · Sheets MVP

Instruction pack for Claude Code. It contains everything needed to build the spreadsheet core (57 field types, views, item panel, automations and triggers, audit trail) and to load the first spreadsheet.

## Start

1. Create an empty GitHub repository and copy this folder into it (keep `.claude/`).
2. Create a Supabase project in **EU (Frankfurt)** and a Vercel project (region `fra1`); fill `.env.local` from `.env.example`.
3. Install Docker (for local Supabase), Node 22 and pnpm.
4. Open the repository in Claude Code and run `/milestone` (M0). Repeat `/milestone` for M1 … M10, one session and one PR per milestone.
5. When M10 is merged, `pnpm seed` loads the first sheet (`templates/first-sheet.json`) and `docs/07-first-sheet.md` is your acceptance walkthrough.

## Checks (CI)

`.github/workflows/ci.yml` runs on every pull request and on every push to `main`, as three jobs side by side so one
failure never hides another:

| Job | What it runs |
|---|---|
| `static` | `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm db:smoke` |
| `database` | local Supabase, `pnpm db:reset` (every migration from scratch), `pnpm db:test` (pgTAP), `pnpm db:types:check` |
| `e2e` | local Supabase, `pnpm seed`, `pnpm build`, `pnpm security:bundle` (no service-role key in the browser), `pnpm e2e` (both projects, about 25 minutes) |

Run the same locally before you open a pull request: `pnpm lint && pnpm typecheck && pnpm test`, then with Docker
`pnpm db:reset && pnpm db:test && pnpm db:types:check`, then `pnpm build && pnpm e2e`.

### Generated types

`src/lib/database.types.ts` is generated from the migrations. Never edit it by hand: when a generated type is wrong
for one use (a column the generator cannot mark nullable, for example), cast it where it is used.

- After adding or changing a migration: `pnpm db:reset && pnpm db:types`, then commit the file with the migration.
- `pnpm db:types:check` regenerates it and fails when it differs from the committed file (the `database` job runs it).
- No Docker? Push the branch and open the pull request. When the `database` job fails at "Generated types are up to
  date", download the run's `database-types` artifact (Actions › the run › Artifacts), unzip it over
  `src/lib/database.types.ts` and commit it.
- The file is generated by the Supabase CLI pinned in `package.json`; do not format it (it is in `.prettierignore`).

### Branch protection (for the repository owner)

Protect `main` so nothing merges red. In GitHub: **Settings › Rules › Rulesets › New ruleset › New branch ruleset**
(or **Settings › Branches › Add branch protection rule** on the classic page):

1. Name `main`, Enforcement status **Active**, Target branches **Include default branch**.
2. Tick **Require a pull request before merging** (approvals: 0 or more, as you like).
3. Tick **Require status checks to pass**, then **Add checks** and add `static`, `database` and `e2e` (they appear
   once the workflow has run on a pull request; the old single check `check` is gone). Tick **Require branches to be
   up to date before merging**.
4. Tick **Block force pushes**. Leave **Restrict deletions** on.
5. Do not add `perf`: the scroll-performance budget runs nightly (`.github/workflows/perf.yml`), because frame times
   on shared runners vary. A red nightly is a signal to look, not a broken main.
6. Save. Admins can still bypass a ruleset only when they are added to its bypass list: leave the list empty.
